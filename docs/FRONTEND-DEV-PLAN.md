The awk tracks `-` lines only (not `+` lines) to avoid the false positive where git re-emits an unchanged x-mm.field as a `+` line because of newline state changes. Side fix: while reviewing the file, I noticed tripwire 4's `/^\\+\\+\\+/` regex had 4 backslashes (the wrong literal); the in_hunk gate made the regex redundant (file headers are always outside hunks, so the gate skips them before the regex runs), so the bug was not user-visible — but the regex was still wrong. Context (` `) lines advance state but do not trip; `-` lines are ignored (removal is the GOOD direction, matching tripwires 1 and 6). A pre-migration file with the defect that only changes a non-style line elsewhere no longer trips. The new behavior matches the W6 rule ("no money-math changes") and mirrors tripwire 6: a REMOVED money-line is the GOOD direction and does not trip. The per-line `<!-- money-travel-on: -->` and block-level `{{-- money-travel-on-block: --}}` overrides continue to work on + lines. Three new self-test assertions cover the additions-only contract. **Sixth tripwire added in `7a30d8bd`**: `number_format(...)` additions in money context. No new marker syntax. Diff-based: scans `+` lines in the working-tree diff with the same `in_hunk` flag pattern as the other diff-based tripwires.
